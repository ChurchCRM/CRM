# ChurchCRM 7.8.7 Release Notes

**Release Date**: November 22, 2026
**Theme**: Database support for the hosting churches actually have

This release cleans up the database-version story. When ChurchCRM raised its database floor to versions that still receive security fixes, the enforcement overshot: churches on the shared hosting most churches actually use — MariaDB 10.6 or MySQL 8.0 — were turned away at install entirely, and our own install data showed real churches stuck at that wall. 7.8.7 fixes that balance: those churches can install, they are told plainly and persistently that their database is out of support, and the safety floor itself does not move. A few reported fixes ride along.

---

## ✨ The Focus: Older Databases

### 🛠️ Fresh installs work on MariaDB 10.6 and MySQL 8.0
A fresh install on MariaDB 10.6 or MySQL 8.0 hosting now goes ahead instead of stopping. In its place, the system carries a clear, persistent banner: this database is out of support and may be unsafe, with the supported versions named — so the church can plan a database upgrade with open eyes instead of hitting a dead end on day one.
* **Where:** any fresh install on MariaDB 10.6 / MySQL 8.0 hosting.

**What did not change:** the supported floor is still MySQL **8.4** / MariaDB **10.11** or newer, and upgrading an existing system still checks the database and stops safely, changing nothing, on an older one. The banner is a warning, not a blessing — those database versions no longer receive security fixes from their makers.

---

## ⚠️ Before You Upgrade

**One automatic step:** during the upgrade, the remaining tables — including your custom-field tables — are converted to the modern text format 7.8.6 began, so names, notes, and custom fields with accents and emoji store and display correctly everywhere. It runs on its own; on a very large database it can add a few minutes to the upgrade.

---

## 🔧 Fixes in This Release

* **Family pages after upgrading:** some churches saw errors on family pages after upgrading when recurring pledges were involved. The upgrade now runs that migration step as part of 7.8.7, and those pages load normally.
* **Reordering custom fields:** changing the order of person and family custom fields could go wrong if the list had changed in the meantime. Reordering now re-checks the current list first, so the order you save is the order you get.
* **Help when ChurchCRM can't start:** the failure page shown when ChurchCRM cannot start now links directly to the Logging & Diagnostics help pages, so the person staring at the error can find the next step instead of guessing.
* **Translation fallback warning:** if a church's language setup leaves no English fallback to display, administrators now see a clear warning instead of silently missing text.
